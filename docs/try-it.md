# DSH Task Pulse：10 分钟试用清单

目标：确认安装是否顺利、侧栏状态是否准确，以及它是否比翻对话记录更容易理解任务进展。建议先邀请 3–5 位已有 DSH 使用经验的朋友。

## 先确认环境

- 插件版本：`dsh-task-pulse@0.1.0`。
- 兼容范围：DSH **0.2.2-rc.1 网页版**，Node.js **>=24.9.0**。Windows 已由作者实测，其他操作系统欢迎按同版本反馈；桌面版未验证。
- 检查 `node --version` 和 `npx @deepseek-ai/dsh@0.2.2-rc.1 --version`。不要为试用覆盖现有配置或升级真实项目环境。
- 使用自己的正常模型配置，在临时项目或已有的测试目录中试用。不需要向作者提供 API Key。

## 安装与打开

```powershell
npx @deepseek-ai/dsh@0.2.2-rc.1 plugin --profile web add dsh-task-pulse@0.1.0
npx @deepseek-ai/dsh@0.2.2-rc.1 web
```

重启 DSH 后，在一个会话中展开右侧栏，点击添加标签页，选择 **Pulse · 任务状态**。不要仅查看标题相似的旧标签页。

项目：https://github.com/Yeti11H/dsh-task-pulse

演示：https://github.com/Yeti11H/dsh-task-pulse/blob/main/docs/demo.gif

## 最小必测

| 场景 | 操作 | 看什么 |
| --- | --- | --- |
| 安装与打开 | 按上述步骤安装、启动和添加侧栏标签页 | 是否能找到面板，有无空白、报错或布局异常 |
| 一次普通任务 | 让 Agent 查看临时项目并运行已有测试；没有测试时只读取几个文件，不要求修改 | 是否能看见等待模型、工具请求、最终完成；很快的状态可能一闪而过 |
| 刷新和设置 | 将静默阈值改为 1 分钟，任务完成后刷新页面 | 设置是否保留，已加载历史是否恢复，是否重复计数 |
| 切换会话 | 打开另一会话再切回来 | 工具、计数和活动是否混入其他会话 |

## 可选边界测试

仅在测试项目里尝试。下面是待收集的真实反馈，不能据此宣称所有场景已经验证通过。

| 场景 | 操作 | 预期 |
| --- | --- | --- |
| 等待用户 | 正常任务触发 DSH 的授权或提问，暂时不处理 | 如果 DSH 提供对应交互信号，应显示等待用户；不代表其他并行工具全部暂停 |
| 用户取消 | 正常任务运行时，用 DSH 原有停止按钮取消 | 本轮显示已停止，不应显示成功完成 |
| 并行工具 | 请求多个独立的只读检查，观察 DSH 是否实际并行发起工具 | 并行请求应分别显示；若 Agent 顺序执行，记为未触发，不能当作并行已通过 |
| 静默 | 将阈值设为 30 秒；让 Agent 使用可用的终端工具等待约 40 秒且不输出 | 仍在运行且没有新活动时出现不确定提醒；它不证明卡死，任何新事件可能重置计时 |
| 断线与重连 | 在测试任务中，使用浏览器开发者工具临时切换离线，再恢复在线；等待 DSH 连接检测 | 观察到断线后应提示连接不可用；重连按 DSH 已加载事件恢复，不保证观察完整 |

不要为了测试故意触发真实服务扣费、删除文件或断开别人的工作环境。模型调用费用仍按你正常使用的服务计费，插件本身不增加模型调用。

## 卸载

```powershell
npx @deepseek-ai/dsh@0.2.2-rc.1 plugin --profile web remove dsh-task-pulse
```

随后重启 DSH。无需删除整个 profile 或用户配置。
